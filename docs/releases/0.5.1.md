# Jonsbo Resurrection v0.5.1

OpenAI usage updates recover correctly, and AI widgets clearly explain when a
subscription sign-in needs attention.

## Changes

- OpenAI monitoring reads the existing native Codex sign-in without forcing an
  OAuth renewal before every poll. In affected clients, the forced renewal could
  return no account even while ordinary account, quota and token-history reads
  still worked. Jonsbo now lets the native client handle normal token renewal.
- OpenAI and Claude widgets replace usage figures with a large amber **Sign in
  needed** notice, **Usage updates stopped**, and an instruction to reconnect
  through Display Studio. The mascot stays still while this notice is visible.
- Expanded widgets also hide cached session token/context figures during this
  state. The healthy usage view returns automatically when sign-in recovers;
  the other provider's widget keeps its own state.

## Download and update

Download `JonsboResurrection-0.5.1-windows-amd64.zip`, extract the complete archive,
and run `JonsboResurrection.exe`. A SHA-256 checksum is provided beside the ZIP.
The archive includes the AI observer, browser bridge/companion, documentation,
images and required dependency notices and source.

Stop the old controller before starting the new copy. Keep
`%LOCALAPPDATA%\JonsboResurrection` to preserve layouts, display assignments and
monitoring preferences. If Windows sign-in startup is enabled, enable the same
startup mode from the new copy to update its registered executable path. See the
[Windows update guide](https://github.com/kawapiki/Jonsbo-resurrection/blob/v0.5.1/docs/windows-app.md#updating-an-installed-copy).

## Validation and limits

Regression checks cover forced-renewal failures, native logout/account changes,
both providers, fan/pump widget sizes, cached values, expanded session figures
and recovery. The installed fix was exercised with the existing elevated startup
task and repeated fresh OpenAI quota and token-history observations. Failure
views were checked with synthetic state without signing out real accounts.
CI uses fixtures and does not access USB or real provider accounts.

Windows amd64 executables remain unsigned. Native subscription monitoring still
requires the supported official clients and their existing subscription sign-ins.
Provider-supplied daily token buckets can lag behind current activity. See the
[AI guide](https://github.com/kawapiki/Jonsbo-resurrection/blob/v0.5.1/docs/ai-subscriptions.md)
for feed coverage and reconnect instructions.

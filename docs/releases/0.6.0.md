# Jonsbo Resurrection v0.6.0

Adds Raijintek Cyclops 360 support and layouts designed for its small circular
screen, while reusing the existing display editor and AI integrations.

## Changes

- Detects the Cyclops 240 × 240 LCD through its factory Windows HID driver.
  Keeps the connection open between frames and recovers on the next refresh
  after a failed transfer. No driver replacement or firmware update is needed.
- Adds ten circular presets: Thermal dial, Graphics dial, Twin temperatures,
  Memory orbit, Processor pulse, System orbit, OpenAI orbit, Claude orbit,
  AI duet, and System + AI.
- Adds transparent rim rings, compact numbers and two-minute history graphs,
  plus circular AI quota rings and small provider status strips.
- Circular AI widgets use the same status, quota and token logic as the existing
  rectangular widgets. Existing connections work without additional activity
  hooks or sign-in setup. Partial and local usage remain identified.
- Consolidates ring drawing and circular masking. Healthy Cyclops connections
  bypass repeated USB discovery. Local rendering benchmarks improved from
  1.02 to 0.59 ms/frame for OpenAI orbit and 1.58 to 1.10 ms/frame for System + AI;
  allocation counts were unchanged. These measure rendering, not USB time or
  total application CPU usage.

## Download and update

Download `JonsboResurrection-0.6.0-windows-amd64.zip` and its SHA-256 checksum,
extract the complete archive, and run `JonsboResurrection.exe`.

Stop the old controller before starting the new copy. Keep
`%LOCALAPPDATA%\JonsboResurrection` to preserve layouts, display assignments and
monitoring preferences. If Windows sign-in startup is enabled, enable the same
startup mode from the new copy to update the registered executable path. See
[the update guide](https://github.com/kawapiki/Jonsbo-resurrection/blob/v0.6.0/docs/windows-app.md#updating-an-installed-copy).

Existing saved layouts keep their composition. Choose a new circular preset in
Display Studio to use the redesign. The archive includes the AI observer,
browser bridge/companion, documentation, dependency notices and required source.

## Validation and limits

Automated checks cover frame bytes, short transfers, cancellation, connection
recovery, circular geometry, layout persistence and shared AI presentation.
Windows tests/vet/builds and portable/editor tests run in CI without physical
hardware or real provider accounts.

The native HID implementation was tested on one Cyclops display. The owner
confirmed steady visible frames at one update per second with the connection
held open. Closing it after a single frame caused the screen to go black; use
continuous `serve --all` or `monitor` for normal operation. Device identity is
based on the USB port, so changing ports can require reassignment.

Windows amd64 executables remain unsigned. Existing sensor-driver and native
AI-client requirements continue to apply. See the
[Cyclops guide](https://github.com/kawapiki/Jonsbo-resurrection/blob/v0.6.0/docs/cyclops.md)
for setup, protocol evidence and benchmark reproduction.
